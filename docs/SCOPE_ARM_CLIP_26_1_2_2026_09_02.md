## 1. 判定依据（静态读码，逐条可复核）

### 1.1 本线的裁剪机制与「掩码纪元」无关

本线是 `DepthCopyRenderType` + `ScopeDepthCopyState`：draw 时把 `tacz_ScopeMaskMode`
打到 2，片元用「世界深度备份 + 目镜孔径深度拷贝」判 `apertureDepth < worldDepth - eps`
丢弃（`scope_flash_clip.fsh` 是 vanilla `entity.fsh` 的逐字克隆 + 前置掩码）。本仓已裁：

| 已裁 | 入口 |
|---|---|
| 枪身 | `BedrockGunModel` → `clipForViewmodel` |
| 配件 | `AttachmentRender` → `clipForViewmodel` |
| 枪口火光（背景层 + 辉光涡旋） | `MuzzleFlashRender` → `flashTranslucentClipped` / `flashSwirlClipped` |
| 镜内文字 | `ScopeTextSubmitter` → `maskedText`（反语义 MASK） |
| mesh GPU 枪身 | `PolyMeshGpuRenderer` → `mesh_entity_scope_clip` |
| **第一人称手臂（本轮）** | `RenderHelper#renderFirstPersonArm` → `wrapForScopeClip` 动态代理 → `flashTranslucentClipped` |

**不裁的**：枪烟 — 本线没有枪口烟渲染件（功能件只有 `MuzzleFlashRender` /
`ShellRender` / `BeamRenderer` / `AttachmentRender` / 左右手 / `TextShowRender`），
仓库里带 smoke 字样的全是 lrtactical 的烟雾弹粒子，无此项可改。

### 1.2 与 26.2 的对照：同类，不是同物

| | 26.2（掩码纪元） | 26.1.2（深度孔径纪元） |
|---|---|---|
| 载体 | `ScopeBodyRenderTypes.armClipped(skin)`，复用 `FLASH_TRANSLUCENT_CLIPPED_PIPELINE` | 复用 `ScopeRenderTypes.flashTranslucentClipped(skin)`（本就是 `entityTranslucent` + 孔径 discard） |
| 掩码来源 | `SCOPE_MASK` 采样器 + `ScopeMaskTextureHandle` | 两份私有深度拷贝（`ScopeDepthCopyState`，`Operation.MASK_OUTSIDE`） |
| 闸门 | `maskReadyForViewmodel(true)`，submit-task 期 | `viewmodelFxClipApplies()` = 目镜序列已登记 **且** 倍率 ≥ `ScopePipMinMagnification`（默认 4×），extract 期 |
| 换 RenderType 的手法 | `SubmitNodeCollector` 动态代理 | 同（手臂的 RenderType 是 `AvatarRenderer` 内部挑的，调用点换不到） |

26.2 复用火光管线的理由与我们相同：火光与手臂在管线状态上无差别（同 blend、同
snippet、同 define）——本线这条管线连 `affectsCrumbling() + sortOnUpload()` 都已齐
（`ScopeRenderTypes#createFlashTranslucentType`，26.2 是为手臂才补的这两项），且已
登记给 Iris 的 `HAND_TRANSLUCENT`。

## 2. 两种 PIP 与整屏变焦 —— 三种模式结论不同（关键）

合成走 `ScopePipRenderState#compositeScene`：`createRenderPass(..., main.getColorTextureView(),
OptionalInt.empty())` —— 没有深度附着，管线是 `ColorTargetState(Optional.empty(), WRITE_COLOR)`
（无混合、全色写），片元只在 `ad < wd - eps`（镜孔内）取样上屏 ⇒ 镜孔区域是无条件
整片覆写。

| 模式 | 合成是否运行 | 手臂会不会挡镜 | 本轮前 | 本轮后 |
|---|---|---|---|---|
| **PIP 重投影**（`ScopePipEnable`，默认关） | 是（合成无深度整片覆写） | **不会** —— 被镜内画面盖掉 | 无缺口 | 无变化（裁了也看不出） |
| **PIP 二次渲染**（`ScopePipRerender`） | 是（窄遍画好后同样走合成；窄遍里手不参与） | **不会** | 无缺口 | 无变化 |
| **光影下 PIP**（`ScopePipAllowShaderPacks`） | 是（Iris final 之后合成） | **不会** | 无缺口 | 无变化 |
| **经典整屏变焦**：PIP 关 / 倍率 < `ScopePipMinMagnification` / 光影下未 opt-in / PIP 失败回退 / 开镜进度 < `PIP_REVEAL_THRESHOLD` 的过渡帧 / 掩码周期不成立 | **否** | **会** —— 手臂挡在目镜里 | **真缺口**（枪身、火光都裁了，唯独手臂没裁） | 已裁（倍率达标时） |

⇒ 26.2 那句 "blocking the see-through/PIP picture" 对本线**只对一半**：
"PIP picture" 那半不成立（合成覆盖），"see-through"（整屏变焦）那半成立。

## 3. 实现

| 文件 | 改动 |
|---|---|
| `com/tacz/guns/util/RenderHelper.java` | 新增带 `clipToScopeExterior` 的 6 参重载；`wrapForScopeClip()` 用 `SubmitNodeCollector` 动态代理把穿过来的 `entityTranslucent(skin)` 换成 `flashTranslucentClipped(skin)`；两条 log-once（成功 `engaged` / 失败 `unavailable`） |
| `com/tacz/guns/client/model/functional/LeftHandRender.java` | extract 期算闸门并传入 |
| `com/tacz/guns/client/model/functional/RightHandRender.java` | 同上 |

**为什么用代理**：手臂的 RenderType 是 `AvatarRenderer#renderLeftHand/renderRightHand`
**内部**挑的（`submitModelPart(arm, pose, RenderTypes.entityTranslucent(skin), ..)`），
调用点换不到；复刻提交就得复刻 vanilla 那串模型状态整备（resetPose / 袖层可见性 /
手臂显隐），版本一动就烂。代理让 vanilla 逻辑原样跑完，只在提交穿过时换掉 RenderType。

**本仓 API 差异**：本仓 `AvatarRenderer` 的两手方法是
`renderLeftHand/renderRightHand(pose, collector, light, texture, slim, player)`（6 参，
含 `PlayerModelType.SLIM` 与 player），姊妹线为 5 参——保持本仓既有调用形态，只把
`collector` 换成代理。

**失败哲学**（与枪身/火光/文字一致）：闸门为假、代理构造抛异常 —— 一律**返回真
collector**，最坏回到「镜内见手臂」的现状，绝不画错手臂。

### 3.1 低倍镜豁免（2026-09-02 追加，姊妹线用户裁定）

**低倍镜（含组合镜的低倍档）一律不裁：手臂、火光、枪身、配件。** mesh GPU 枪身
同此（`PolyMeshGpuRenderer` 的 apertureClip 在 `hasMaskCycleThisFrame()` 之外再加同一条
倍率线）。

- 判定：`ScopeRenderTypes#viewmodelFxClipApplies()` = 目镜序列已登记 **且**
  `ScopePipRenderState#currentZoom() >= ScopePipRenderState#minMagnification()`
  （= `ScopePipMinMagnification`，默认 **4×**，配置范围 1–100）。
- 组合镜按**当前档位**判定：倍率取 `IGun#getAimingZoom`（与 PIP 判定同一个值），
  切到低倍档自动不裁，切回高倍档自动裁。
- **更正早期说法**：枪身那一刀**不是**「把镜片挖透、与倍率无关」——实读
  `BedrockAttachmentModel#currentAimingProgress` 注释：开镜进度过 `AIM_CLIP_START` 后，
  活动 ocular 就已经从可见 body 移到 invisible depth writer（与倍率无关），镜片区域
  本来就是透的。所以枪身/配件这一刀与手、火光**同性质**：都是「给镜内画面让位」。
  低倍镜没有放大画面可让位 ⇒ 裁掉的是枪身自己，观感就是枪身上破个洞。
- 理由：手臂/火光那一刀的作用本是「给镜内放大画面让位」；低倍镜阈值以下连 PIP 都不跑，
  挖出来的洞里是**没放大的背景**，观感就是手上/火光上破了个洞。

## 4. 实机验收清单（**本沙箱无运行环境，全部未验**）

1. 装**高倍镜（≥ `ScopePipMinMagnification`，默认 4×）**、**关掉 PIP** → 开镜：目镜圈内
   **不应出现手臂/袖子**（枪身与火光同闸门，作对照组：它们应当照旧被裁）。
   注意别用低倍镜做这条 —— 低倍镜按 §3.1 本来就不裁。
2. 打开 PIP（重投影 / 二次渲染各一遍）→ 与改动前**一致**，不得出现新瑕疵。
3. 日志：应出现一次 `[TACZ Scope] In-scope arm clipping engaged: ...`。
   若出现 `unavailable` → 代理没建成，行为等同现状（不崩）。
4. 低倍镜 / 无瞄具 / 关镜状态 → 手臂完全正常（闸门为假时走原 collector）。
5. 装 PlayerAnimator / NEA → 手臂与袖层不错序、不缺件。
6. 光影下 → 手臂按 `HAND_TRANSLUCENT` 程序走，无黑臂、无错序。

**低倍镜豁免的验收（追加）**

7. 装红点/全息/2×/3× 瞄具开镜 → 目镜圈内**手臂与火光正常绘制**（不得出现破洞），
   且 `latest.log` **不应**出现 `In-scope arm clipping engaged`。
8. 组合镜（可变倍）在**低倍档**开镜 → 同第 7 条；**切到高倍档** → 同第 1 条（裁手、有日志）。
   切档是即时生效的，不需要重启。
9. 4× 及以上：与第 1-6 条一致，不得倒退。
10. **枪身 / 配件**（同上豁免）：低倍镜开镜时，镜孔圈内应当看到**枪身自己的几何**
    （透过镜片看见枪，而不是一个穿透枪身露出背景的洞）；高倍镜则照旧被裁。
    mesh GPU（高模）枪身同此 —— 装 meshloader 的枪也要验一遍，它走的是另一条批次。

## 5. 未验项与已知风险（AGENTS §2：不夸大）

- **`RenderTypes.entityTranslucent` 是否按贴图 memoize**：这是 26.2 侧的**字节码实读**
  结论，本线没有 `javap` 复核（沙箱无 Java 工具链）。**若未 memoize，identity 比较
  永不命中 ⇒ 效果等于没做**，且不报错、不崩 —— 注意：此时**日志仍会打 `engaged`**
  （代理建成 ≠ 真的裁掉了）。这是实机第 1 条要盯的点：日志有了但目镜里还有手，
  就是这一处。
- **`SubmitNodeCollector` 是接口**：由
  [`SCOPE_FINAL_OVERLAY_BACKPORT_26_1_2_2026_08_30.md`](SCOPE_FINAL_OVERLAY_BACKPORT_26_1_2_2026_08_30.md)
  证实（`SubmitNodeStorage` … `implements SubmitNodeCollector` ✓）；另加运行期
  `isInterface()` 兜底（代理失败回真 collector）。
- **每帧两次手臂提交的反射开销未测**（26.2 评估为可忽略）。
- **双持 / 副手边界**：闸门在 extract 期取值，同一 flush 里后一把枪的目镜状态会覆盖
  前一把的判定（极端边界，未验；最坏是某一只手不裁，回到现状）。
