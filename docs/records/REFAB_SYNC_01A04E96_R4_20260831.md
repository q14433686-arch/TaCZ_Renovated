## 3. 本轮搬了什么（`2a408c7`）

全部落在**已经发船的手部 GPU 路径**上，世界语境一行没动。

1. **法线弹栈时序**（`83daf16`，真 bug）：`drawListViaRenderType` 里把
   `mvStack.popMatrix()` 从 `prepare()` 之后移到 `drawFromBuffer()` 之后。
   证据（Iris 26.2 `ExtendedShader.iris$setupState` 源码实读）：光影包的
   `gl_NormalMatrix` 是**绘制执行那一刻**从 `RenderSystem` MV 栈顶取的逆转置，
   不走 `prepare()` 快照；弹早了 ⇒ 栈顶只剩 MV_draw ⇒ 骨骼本地法线转错方向。
   **位置不受影响**（ModelViewMat 走 prepare() 快照），所以肉眼容易漏——
   这是「光影下反光的光源关系不对」那类症状。
2. **A3**：两处 catch 补 `LinkageError`。Iris/Sodium 升级后签名变了抛的是
   `NoSuchMethodError`（Error 不是 Exception），漏接 = 崩游戏而不是回退 collector。
3. **A2**：GPU 失败不再回写 `MeshyConfig.GPU_BAKING`。渲染线程写配置文件既不安全，
   也会把一次瞬时故障固化成用户看不懂的持久设置；只置会话标志。
4. **A5**：逐帧比对 `DefaultVertexFormat.ENTITY.getVertexSize()`，stride 变即整代失效
   （原来只认光影开关翻转；别的 mod 改顶点格式同样会让旧 VBO 被按新 stride 解读 = 拉伸）。
5. **A1（防御）**：手部消费点带 `RenderSystem.outputColorTextureOverride` 时跳过并清表。
   26.2 字节码显示 vanilla 只在 `addAlwaysOnTopPass` 设它，防的是别的 mod。
6. **A10 里唯一无争议的一条**（无配置净收益）：`PolyMesh` 退化面（零面积）不再写零法线
   —— `normalize(0)` = NaN，光影下是随机高光/黑点；退化为枪包自带法线，再不行取 (0,1,0)。
7. **A7 命名**：`handModelView` → `drawModelView`（与她同名，纯可读性）。
