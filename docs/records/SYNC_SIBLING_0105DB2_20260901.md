## 8. 第三轮修正：光影下世界 GPU 路径枪体不可见（用户报告，2026-09-02 晚）

- **用户报告**：开光影 + `MeshGpuWorldUnderShaders` 默认开 ⇒ 第三人称 / 掉落物 / 展示台
  高模 mesh 枪不显示。
- **根因（读码定位）**：本线 `IrisCompat#isRenderShadow` 是 `return false` 空壳
  （移植前即如此——`e3d9dd5` 时点该行原样；姊妹 1.21.11 线
  legacy/newly 双桥均反射 `net.irisshaders.iris.shadows.ShadowRenderingState#
  areShadowsCurrentlyBeingRendered()`，语义权威）。Iris 1.10.x 阴影 pass 经
  `MixinGlCommandEncoder` 拦截 `glBindFramebuffer` 切 FBO（不走
  `outputColorTextureOverride`）⇒ drawList 的 override 闸挡不住阴影 pass ⇒
  阴影 pass 的 `renderAllFeatures` 调用点消费世界 GPU 表并标记 `worldConsumedFrame` ⇒
  主画面那遍见 `worldConsumedFrame == frameId` 直接返回 ⇒ 主画面不可见。
- **修法**：`isRenderShadow()` 按姊妹线同款反射实现 + ModList 前置检查 + Throwable 兜底
  false。同步受益：`PolyRenderPolicy` 阴影提交闸、`ShellRender` / `MuzzleFlashRender`
  阴影闸恢复真实信号（同源空壳的另三处调用）。
- **证据**：Iris 上游 `1.21.11-unobf` 分支 common 模块直读
  `ShadowRenderingState.java`（gh api）：`public static boolean
  areShadowsCurrentlyBeingRendered()` 存在，common 为加载器无关模块（NeoForge 构建同源）。
- **待实机**：开光影 + 默认开关下第三人称/掉落物/展示台高模枪可见；阴影贴图里枪影形状
  正常（cube-only 阴影是设计语义）；shell/muzzle 在光影下的表现复核。
- **26.1.2 分支澄清（维护者 2026-09-02 实机结论）**：26.1.2 分支同名方法也是空壳，但
  该线**实机 PASS、无此症状**——空壳致命是本线 1.21.11「世界表消费点挂在
  `renderAllFeatures` RETURN」的拓扑特有的。故 26.1.2 分支不随本轮改动，本文档及
