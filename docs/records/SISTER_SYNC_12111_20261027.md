## 工作台：不能只移除手工掉落

旧版 `AbstractGunSmithTableBlock#playerWillDestroy` 在生存模式挖非根半边时手工生成克隆，而本线额外的 `affectNeighborsAfterRemoval` 在相应的邻接更新之前用 `removeBlock(companion, false)` 静默清除另一半。因此上次审计保留这两处是有原因的：**仅删手工掉落会丢失根半边掉落**。也不能把姊妹线修前的「双倍掉落/创造漏物」直接说成本线实测现象，本线原有提前清除路径不同。

本轮经过下列顺序核对后**同时移除**手工掉落与提前清除，让 B/C 的 `updateShape` 清除另一半：

1. [1.21.11 `LevelChunk#setBlockState`](https://github.com/RecaniteButOnGit/Minecraft-1.21.11/blob/2ad63c9eb745f825988e8d73ef4719688fd67b59/server/world/level/chunk/LevelChunk.java) 的 `affectNeighborsAfterRemoval` 发生在 `Level#setBlock` 随后的邻接形状更新之前。旧的提前删除会绕过根半边 loot。
2. [1.21.11 `Level#setBlock/removeBlock/destroyBlock`](https://github.com/RecaniteButOnGit/Minecraft-1.21.11/blob/2ad63c9eb745f825988e8d73ef4719688fd67b59/server/world/level/Level.java) 邻接传播使用 `flags & -34`，清掉 `UPDATE_SUPPRESS_DROPS`；[`Block#updateOrDestroy`](https://github.com/RecaniteButOnGit/Minecraft-1.21.11/blob/2ad63c9eb745f825988e8d73ef4719688fd67b59/server/world/level/block/Block.java) 将变为空气的邻居交给 `destroyBlock`。原版源码使用公开的第三方反编译，**不是**本地运行证据。
3. [`ServerPlayerGameMode` 的 NeoForge 1.21.11 patch](https://github.com/neoforged/NeoForge/blob/0753a6a7dd9ed0bafc5441142206f33618f031b3/patches/net/minecraft/server/level/ServerPlayerGameMode.java.patch) 在破坏前取得被挖半边的方块实体，`onDestroyedByPlayer` 默认调用 `removeBlock`（[接口源码](https://github.com/neoforged/NeoForge/blob/0753a6a7dd9ed0bafc5441142206f33618f031b3/src/main/java/net/neoforged/neoforge/common/extensions/IBlockExtension.java)）。挖根时 `playerDestroy` 使用已取出的根实体；挖非根时，根的 `destroyBlock` 在移除前取得根实体。工作台 loot 只对 `part=foot` / `half=lower` 产出，枪包工作台 `copy_custom_data` 从根实体拷贝 `BlockId`。
4. B 型创造模式守卫改为挖 HEAD 时静默清除有 loot 的 FOOT；C 型原本就是挖 UPPER 时清除 LOWER。根的主动破坏由创造模式本身抑制，非根邻居不产物。
5. [Carry On 2.9.2 `PickupHandler#tryPickUpBlock`](https://github.com/Tschipp/CarryOn/blob/c65c63fbe1f6a089fc5afb1fc38d469f9f36262c/Common/src/main/java/tschipp/carryon/common/carry/PickupHandler.java) 在**允许拾取**时保存根状态/实体后调用 `removeBlockEntity`、`removeBlock(pos,false)`；后者仍传播邻接更新。现有 `CarryOnPickupHandlerMixin` 意图先把点击非根重定向至根，因此剩余非根走自身的空 loot，不应掉出工作台；[`PlacementHandler`](https://github.com/Tschipp/CarryOn/blob/c65c63fbe1f6a089fc5afb1fc38d469f9f36262c/Common/src/main/java/tschipp/carryon/common/carry/PlacementHandler.java) 通过 `setBlockAndUpdate` 放根，本线 `onPlace` 重建另一半，放置 mixin 保留空间预检。Carry On 的 `hasPropertyType` 按值类型拒绝原版 `DoubleBlockHalf`；本线 C 型使用自有 `TableHalf` 枚举（序列名仍为 `lower` / `upper`），因此不因该特定条件被拒，但仍受名单、距离、配置及其他检查约束。以上是按源码推演，**未在安装 Carry On 的游戏里验证 mixin 或实际可拾取性**。

此方案让正常破坏以 loot 为唯一产出点，并保留原有克隆/拾取菜单逻辑。外部模组若使用不传播邻接更新的特殊标志，或拦截这些事件，其行为不在本轮验证范围内。

## 雕像与标靶

| 项 | 处理和边界 |
|---|---|
| 雕像持枪 | 覆写 `BlockEntity#preRemoveSideEffects(BlockPos, BlockState)`，在服务端用传入的旧状态方向掉枪，清空栈避免重复；没有朝向属性时安全回退 NORTH。`super` 仍被调用。参考 [1.21.11 BlockEntity](https://github.com/RecaniteButOnGit/Minecraft-1.21.11/blob/2ad63c9eb745f825988e8d73ef4719688fd67b59/server/world/level/block/entity/BlockEntity.java) 和 `LevelChunk#setBlockState` 调用点。此钩子不覆盖带 `UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS` 的特殊移除。 |
| 标靶放置与矿车 | 本线原有 `new GameProfile(null, name)` 在 authlib 7 上会抛异常；[姊妹线实际依赖探针及 CI 记录](https://github.com/q14433686-arch/TaCZ_Refabricated_Unofficial/blob/aac343af891858589eaea69bbefc413c0f2b1977/docs/lineage/SYNC_REVIEW_262_TO_1211_20261027.md) 提供旁证。改用 `TargetOwnerProfiles#fromName` → `ResolvableProfile#createUnresolved(String)`，矿车按自定义名变化刷新缓存，空名无头像。 |
| 存档/同步 | `TargetBlockEntity#loadAdditional/saveAdditional` 对称读写 `owner_name`，允许非玩家名及长名，既有扁平 `owner_name` 可读，旧 `owner_uuid` 不使用；更新包也经过此路径。缺失字段时清空旧值，损坏的旧 JSON 名称不使区块读取抛异常。**与姊妹 1.21.11 相同，本轮不读取上游 `Owner` 复合标签或 26.2 新 `profile` 格式，也不保留 UUID-only 档案**；跨格式迁移仍待单独处理。 |
| 客户端皮肤 | 标靶和矿车共用 `TargetOwnerSkins`，渲染状态提取时通过 `Minecraft#playerSkinRenderCache()` → `PlayerSkinRenderCache#getOrDefault(ResolvableProfile)` 异步查询，失败回退默认皮肤并只警告一次；矿车提交几何时仅使用已提取的贴图。实际联网、离线及无效名字均未实测。 |
| NeoForge 持久化 | 两个方块实体的 `loadAdditional(ValueInput)` / `saveAdditional(ValueOutput)` 调用 `super`；[NeoForge 1.21.11 BlockEntity patch](https://github.com/neoforged/NeoForge/blob/0753a6a7dd9ed0bafc5441142206f33618f031b3/patches/net/minecraft/world/level/block/entity/BlockEntity.java.patch) 在父类处理 `NeoForgeData` 与附件。这是 Fabric 代码不能直接整文件覆盖的差异。 |
