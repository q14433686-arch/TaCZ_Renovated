## 3. 本轮同步了什么

### 3.1 检视动画两连修（她的最高优先）

两笔**必须一起拿**：

- `4aa8d7b`：让 `stopAnimation` 连坐 `transitionTo` —— 带过渡时长启动的动画在过渡完成前
  挂在旧 runner 的 `transitionTo` 上，只停当前 runner 等于停了个寂寞；
- `12d6f3c`：引入 runner **出生序号** + `AnimationStateMachine#trigger` 的转移前快照
  （`triggerSpawnFloor`，栈式恢复以支持脚本重入 trigger），豁免「本次 trigger 刚启动的
  后继动画」—— 只拿第一笔会引入「检视中换弹，换弹动画被 exit 的 stop 当场误杀」的新 bug。

病根她写得很清楚：开镜时检视，脚本 `inspect.transition` 的打断分支会被每 tick 的移动类
输入在 ≤50ms 内触发，必然落在 0.2 秒过渡窗口内 → 检视动画成了无主僵尸，状态机已回
idle，挂在 inspect 态上的打断手段全部失联，只有切枪/丢枪能救。

落地：三文件改后与她 `12d6f3c` 终态**逐字相同**，无 Fabric 残留，无加载器差异。
CI 已过（`c65d9dd`：BUILD SUCCESSFUL）。

### 3.2 `ScopePipRerenderInterval` + ResolutionScale 作用域

- 新旋钮 `ScopePipRerenderInterval`（1~4，默认 1）：二次渲染模式下镜内那一遍世界每 N 帧
  才真跑一次，其余帧复用离屏纹理里的上一帧成品。这是**光影下唯一砍得到大头的杠杆**
  —— 帧率对半的根因是整条 Iris 管线每帧跑两遍，降离屏分辨率救不了它。
- 两道守卫：`ScopePipTarget.generation()` 必须一致（target 重建后新纹理内容未定义）、
  帧差 `< N`（`frameIndex` 只在 `GameRenderer#extract` HEAD 递增，每帧恰一次，
  不受 Iris 一帧两趟手部 pass 影响）。首帧哨兵 `Long.MIN_VALUE` 会让
  `frameIndex - MIN_VALUE` **上溢成负数**，所以额外加了 `lastScopePassFrame >= 0`。
- `ScopePipResolutionScale` 的真实作用域（只在「二次渲染 + 无光影」生效）补进配置注释、
  Cloth tooltip、中英文文案，并在两条不消费它的路径各打一条一次性日志。

取证：`ScopePipTarget` 改动前与她 `9df8718^` 除 `@Environment` 与注释措辞外逐字相同；
四个插入点结构一致。按本仓 `ModConfigSpec.IntValue` 表面接入，未照抄 `ForgeConfigSpec`。

## 4. 不同步什么，以及为什么

### 4.1 `4ec0dde` ShadowScale 热应用 —— 依赖本仓刻意没有的装置

她的做法是：记下建管线时的 `appliedShadowScale`，在 `prewarmIfNeeded()` 里每帧比对，
变了就 `releaseScopePipelineIfPresent()` 销毁重建。
而本仓 `IrisScopePipelineCompat` 是 **219 行的精简版**（她的 353 行），文件头的移植说明
白纸黑字写着「未同步那套『空闲释放瞄具管线』的实验入口，它是未结案调查的探针，不是修复」。
热应用**就长在那套装置上**，拆不出来。

本仓现状是诚实的：配置注释末行写着 `Takes effect when the scope pipeline is built, so
restart or change dimension.` —— 限制已知、已写明，不是静默失效。
她的 `4ec0dde` 里另一半「钩子静默失效告警」（`shadowHookRanDuringBuild`）倒是**值得单独拿**：
`IrisShadowResolutionMixin` 是 `require = 0` 的软注入，Iris 改内部类名它就悄悄不生效，
把静默变告警对排查有价值。**留给下一轮。**
