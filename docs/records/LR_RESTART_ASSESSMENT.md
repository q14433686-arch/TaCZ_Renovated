# LR 内置层重启评估（2026-08-21）

> 决策支持文档。问题：WP⑦（LRTactical 内置）于 Beta-1 撤回后，现在要不要重启？
> 调研输入：本仓库 records/WP07（13 条踩坑全记录）、refab `26.2(main)`
> `docs/LRTACTICAL_FEEDBACK_LAYER_26_2.md`（2026-08-12）、R1 全部实测记录。

## 一、当时为什么撤回（复盘）

r26 立项（形态 B，104 文件 + 31 个 json/lua 资源）→ 三轮修复（注册表冻结 A 类、
私有化 B 类逐一解决）→ **r30 修完全部已知问题后仍崩，且崩溃日志未上传、无法定位**
（E-13）→ 项目优先稳定性，撤回。

**撤回的直接原因不是"太难"，是"瞎子调试"——拿不到日志。**

## 二、撤回之后变了什么（重启可行性的四个增量）

| 当时的障碍 | 现在的状态 |
|---|---|
| E-13：崩溃日志拿不到 | **日志回路已打通**：R1 战役五份实测记录全部当日往返（main 分支传 log → 定位 → 修复 → 复测），r30 式"未定位崩溃"不复存在 |
| 26.1 NeoForge 语义生疏（注册冻结/时序/类加载） | 恰好是 R1 战役反复锤炼的领域：A 类坑（冻结时序）有全套解法记录；@OnlyIn 无保护、codec EMPTY、dist 类加载全部实战过 |
| 预定重启方案（DeferredRegister 全量重写 init 包）未验证 | 该习语就是本仓库全部 `init/` 的现行写法，照抄自己即可 |
| refab 侧 LR 语义还在演进 | 已成熟一轮：反馈层（三类 tooltip / 使用进度 HUD / 分类冷却遮罩）2026-08-12 完成并文档化；flash_shield 明确排除（独立子系统 + ARR 美术，约 700-1000 行，上游自己也不做） |

## 三、仍然真实存在的成本与风险

1. **体量**：104 文件迁移 + init 包重写 + 反馈层的 NeoForge 适配。好消息是反馈层
   三件套的 NeoForge 对应物全是本仓库已在用的：tooltip →
   `RegisterClientTooltipComponentFactoriesEvent`；HUD → `RegisterGuiLayersEvent`；
   冷却遮罩 mixin → 独立 mixin 配置（WP07 D-10 已验证的形态）。
2. **E-13 幽灵**：r30 崩因至今未知。但"未知崩溃 + 有日志回路"= 普通调试任务，
   预期 1-3 轮往返收敛（对照：R1 战役四个 bug 平均当日闭环）。
3. **联机面**：投掷物实体（spawn 数据）、`ServerMessageCustomCooldown` 类同步消息、
   近战事件——全是多人故障高发区。**refab 的 LR 专服验证至今未做**（其反馈层文档
   实测清单第 6 条仍是待办，且其专服当前被创造栏问题挡着）——我们做完 LR 专服
   验证反而能第三次回哺上游。
4. **协调成本**：26.2 前滚（01a023e5）正从 R1 基线走。LR 若立即上 26.1.2 主线，
   他的基线又要动。

## 四、结论：做，但锁三个约束

**判定：中等难度、高确定性**——所有已知雷区有地图（13 条踩坑记录），唯一的
未知项（E-13）已从"不可定位"降级为"普通调试"。当前团队状态是历史最佳窗口。

约束：

1. **时机与分支**：R1 发布之后启动，作为 26.1.2 维护线的 **R2 目标**，
   在独立分支上做；26.2 前滚继续以 R1 为基线不受扰动，LR 在 26.1.2 验证
   稳定后再平移 26.2（LR 本就要做两次适配，顺序上先在熟悉的版本线收敛语义）。
2. **方案锁定**（WP07 重启前置条件照单执行）：DeferredRegister 全量重写 LR init
   包（根除 A 类时序）；LR mixin 独立配置文件；flash_shield 继续排除；
   美术 ARR 零打包（refab 的 31 个资源全为 json/lua，已核）。
3. **验收门槛**：启动冒烟 → 单机功能（refab 反馈层文档的实测清单 1-5）→
   **专服 LR 专项**（投掷物 tracking 同步、冷却消息、近战事件；LR 网络消息
   按"ItemStack 字段先问会不会 EMPTY"纪律逐条过）。三关全过才进 R2。

预估节奏：2-3 个 AGENT 工作会话 + 3-5 轮用户实测。第一轮的唯一目标就是
**重建 r30 状态并拿到那份迟到的崩溃日志**——E-13 定位成功即宣告最大不确定性消除。
