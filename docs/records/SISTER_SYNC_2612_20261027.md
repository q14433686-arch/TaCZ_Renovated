## 1. 工作台：与本仓 1.21.11 一致，同时移除手工掉落与提前静默清除

本线修前 `AbstractGunSmithTableBlock`、`GunSmithTableBlockB/C`、`CarryOnPickupHandlerMixin`、`CarryOnPlacementHandlerMixin` 及六份方块战利品表与本仓 `1.21.11` 修前逐字一致：

1. 旧基类既有生存模式挖非根半边的手工 `popResource(getCloneItemStack(...))`，又有 `affectNeighborsAfterRemoval` 在邻接形状更新之前调用 `level.removeBlock(companionPos, false)`。若像姊妹 Fabric `26.1.2` PR #119 那样只移除 `playerWillDestroy` 而保留 NeoForge 本线的 `affectNeighborsAfterRemoval`，挖非根半边时根半边仍会被提前无掉落移除，导致生存模式不掉工作台。
2. 同时移除 `playerWillDestroy` 与 `affectNeighborsAfterRemoval` 后，破坏任一半边统一经 `GunSmithTableBlockB/C#updateShape` → `Block#updateOrDestroy` → `Level#destroyBlock(..., true)` 清除另一半，正常生存破坏以根半边战利品表（`part=foot` / `half=lower`，枪包工作台由 `copy_custom_data` 拷贝 `BlockId`）为唯一产出点。
3. `GunSmithTableBlockB#playerWillDestroy` 创造模式抑制判据翻正为挖 `HEAD` 时静默清除带战利品表的 `FOOT`（`Block.UPDATE_ALL | Block.UPDATE_SUPPRESS_DROPS`）；`GunSmithTableBlockC` 原本就是挖 `UPPER` 清除 `LOWER`，且保留自有 `TableHalf` 枚举避免被 Carry On 按原版 `DoubleBlockHalf` 值类型直接拒绝。
4. Carry On 兼容仍由 `CarryOnPickupHandlerMixin` 将非根点击重定向到根方块，拾取保存根方块实体后调用 `removeBlock(pos, false)` 触发邻接更新清除非根半边；放置时由 `AbstractGunSmithTableBlock#onPlace` 重建伴随半边，`CarryOnPlacementHandlerMixin` 保留空间预检。此为源码静态核对，**未在安装 Carry On 的 26.1.2 客户端/服务端实机验证**。

## 2. 雕像、标靶与标靶矿车

| 项目 | 本线处置与边界 |
|---|---|
| 雕像持枪掉落 | 覆写 `StatueBlockEntity#preRemoveSideEffects(BlockPos, BlockState)`，服务端读取回调传入的移除前 `BlockState` 获取 `FACING`（缺失属性回退 `Direction.NORTH`）掉出枪械并清空 `gunItem`，防止重复掉落；保留 `super.preRemoveSideEffects` 调用。不覆盖带 `UPDATE_SKIP_BLOCK_ENTITY_SIDEEFFECTS` 的特殊移除。 |
| 标靶放置与矿车档案 | 修前 `TargetBlock#setPlacedBy` 与 `TargetMinecart#getGameProfile` 使用 `new GameProfile(null, name)`，authlib 7+ / 9 的 `GameProfile` record 构造器对 null UUID 抛 `NullPointerException`（导致改名标靶放置中途异常中断、改名标靶矿车在渲染状态提取阶段崩溃）。统一改走 `TargetOwnerProfiles#fromName` → `ResolvableProfile#createUnresolved(String)`，空白名返回 `null`，异常收敛并记 WARN；`TargetBlock#setPlacedBy` 保留本线既有的 `sendOverlayMessage` 等 26.1.2 API，在设置 `CustomName` 后调用 `setOwner` 一次性触发 `refresh()`；`TargetMinecart` 保留本线 `sendSystemMessage`，按自定义名缓存 `ResolvableProfile`，改名或清名时自动刷新。 |
| 标靶存档与同步 | 与本仓 `1.21.11` PR #64 一致，`TargetBlockEntity#loadAdditional/saveAdditional` 对称读写扁平字符串 `owner_name`（而不采用姊妹 `26.1.2` PR #119 的 `ResolvableProfile.CODEC`，因 `Partial` 玩家名校验拒绝超 16 字符或含空格/中文的自定义名）。缺失键时清空旧 `owner` 与 `name`，避免区块重读或更新包残留旧状态；损坏的旧 `CustomName` JSON 退回字面量文本，不中断区块加载。与 `1.21.11` 线相同，本轮不迁移上游 1.20.1 `Owner` 复合标签、仅 UUID 档案或 `26.2` 的 `profile` 键。 |
| 客户端异步皮肤与提取阶段解耦 | 新增 `TargetOwnerSkins#texture(ResolvableProfile)`，经 `Minecraft.getInstance().playerSkinRenderCache().getOrDefault(profile).playerSkin().body().texturePath()` 非阻塞获取皮肤，运行期异常只打一次 WARN 并退回 `DefaultPlayerSkin.get(profile.partialProfile()).body().texturePath()`。`TargetRenderer`（保留 26.1.2 `state.level.CameraRenderState`）与 `TargetMinecartRenderer`（保留 26.1.2 `BlockModelRenderState`）均在 `extractRenderState` 阶段解析出 `Identifier` 贴图，`TargetMinecartRenderer#submitMinecartContents` 仅消费已提取贴图（修正姊妹 `26.1.2` PR #119 仍在提交阶段做查询的做法，彻底移除直接 `SkinManager` 调用）。 |
| NeoForge 父类持久化 | `StatueBlockEntity` 与 `TargetBlockEntity` 的 `loadAdditional(ValueInput)` / `saveAdditional(ValueOutput)` 补齐 `super` 调用（`GunSmithTableBlockEntity` 原本已有），保留 NeoForge `BlockEntity` 父类的 `NeoForgeData` 与附件读写。 |
