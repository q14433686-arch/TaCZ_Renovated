## Ported changes

1. **Two-block gunsmith tables**
   - Removed `AbstractGunSmithTableBlock#affectNeighborsAfterRemoval`'s early silent companion clear. Companion removal now runs through neighbor updates, preserving the root loot-table path.
   - For B tables, creative destruction of `HEAD` now removes the loot-bearing `FOOT` root with drop suppression. Loot tables remain the source of normal drops and `BlockId` copying.
   - Preserved the existing Carry On pickup redirection to the root half and placement-space preflight. Source inspection is not an in-game compatibility result.

2. **Statue held item and NeoForge persistence**
   - Moved removal drops to `StatueBlockEntity#preRemoveSideEffects`, using the callback's old `BlockState` for facing, server-side only, and clearing the stack before spawning it to prevent duplicate drops.
   - Added `super.preRemoveSideEffects`, `super.loadAdditional`, and `super.saveAdditional` calls.

3. **Target owner profile migration / asynchronous lookup**
   - Persist `ResolvableProfile` while retaining `owner_uuid` / `owner_name` flat keys and accepting the legacy `Owner` compound (`Name` / `Id`) as well as its string form.
   - Keep `GameProfile` integration accessors, but avoid constructing profiles with a literal null UUID; newly placed named targets use a dynamic name profile.
   - Resolve names or UUIDs on `Util.nonCriticalIoPool`, return to the server thread, and reject stale callbacks using removal state, level, requested-profile identity, and generation.
   - Keep resolved owners dynamic by UUID so the client skin cache can fetch current textures rather than persisting a server-side skin snapshot.

4. **Target skins**
   - Block and minecart renderers obtain skin data through 26.3 `PlayerSkinRenderCache` during render-state extraction; submission no longer waits on `SkinManager#createLookup(...).get()`.
   - Retain a default-skin fallback and clear stale per-frame render state when there is no owner.

5. **Static CI guards**
   - Added `scripts/verify_block_drops.py` for 26.3 loot schema, root-half conditions, workbench `BlockId` copy, creative guards, neighbor updates, and Carry On mixin wiring.
   - Added `scripts/verify_block_entity_persistence.py` for item-bearing block-entity removal policy, NeoForge parent persistence calls, profile migration/async guards, null-UUID construction, and skin-cache use.
   - Added `scripts/test_block_guards.py` with one baseline self-check and six mutation cases proving known bad loot-schema, creative-side, persistence, stale-callback, and renderer-cache variants are rejected.
   - Added strict checks and mutation tests to `consistency.yml`; added `26.3` to the compile-check and full-build push filters. The release workflow remains restricted; no release was requested.
