## 1. 掩码凸包：26.2 上拿不到手持投影，硬件裁剪必须撤

### 1.1 症状（本仓踩过的两次）

- 第一次：开镜时**朝南**被切成矩形——裁剪盒拿错了矩阵（把视图矩阵当投影矩阵用）。
- 第二次：改成从正确来源取之后仍然不对，因为**手持那一遍的投影矩阵在 26.2 的 CPU 侧根本拿不到**。

她那边目前的形态（她 `ScopeMaskRenderer` 2026-08-22 版）就是这条死路：
`NDC_SANITY_LIMIT`、`MASK_BOUNDS_NDC`、`maskBoundsNdc()` / `hasMaskBounds()`
——出口是给硬件裁剪用的边界，而边界需要那个拿不到的投影。

### 1.2 我们改成什么

**删除整条硬件裁剪路径**，改为在**凸包写入阶段**做离群剔除（`applyOutlierTrim`）。
好处是它完全不需要投影矩阵：整个判据建立在「斜率空间」和「相对中位数」上。

三层，从粗到细：

1. **绝对斜率上限** `SLOPE_SANITY_LIMIT = 3.0`：丢弃 `|slopeX|` 或 `|slopeY|` 超限、
   或不是有限数的点。这一层挡的是**近平面炸包**——某个顶点擦过近平面时 `depth → 0`，
   斜率被放大上百倍，一个点就能把凸包撑爆。
2. **半径离群**（`RADIUS_OUTLIER_FACTOR = 5.0`）：丢弃到稳健中心（x/y 的中位数）的距离
   超过 `中位数半径 × 5` 的点。为什么还要这一层：第 1 层是**投影相关**的——开镜变焦把 P
   放大数倍，同一个斜率上限换算到 NDC 就松了同样的倍数；而「离群」本质是**相对**概念：
   目镜玻璃自己占绝大多数点，中位数半径就代表孔径本身，筒壁 / 压圈 / 误挂在目镜节点下的
   其它几何必然落在数倍之外。5.0 是刻意保守：玻璃自身外缘最多约中位数的 1.5 倍，
   留三倍余量，**宁可漏剔（退化为旧行为）也不能把孔径本身削掉**。
3. **深度离群**（`DEPTH_OUTLIER_FRACTION = 0.25`）：丢弃视深度 < `中位数深度 × 0.25` 的点。
   近平面伪影的判据不是「斜率大」而是「深度趋零」：同一目镜上玻璃片在 0.2 格处，
   擦过近平面的顶点在 0.002 格处，后者斜率放大上百倍——但**深度本身**不撒谎。

中心用**中位数**而不是均值：单个离群点就能把均值拽走，中位数拽不动。

### 1.3 一个必须记下的坑：阈值是「量级」不是「常数」

本仓 `b5ac13d`（2026-08-30）补的一笔：MARK5 在**开镜渐开过程中**掩码渐开超出目镜。
根因不是阈值太小，是**换算量级错了**——斜率空间和 NDC 空间之间差一个投影缩放，
写死一个数在 1× 和 6× 倍率下是两回事。

⇒ 判据要写成「相对中位数」或「显式除以当前投影缩放」，不要写成一个不随倍率变化的常数。

### 1.4 验收

- 开镜**渐开全过程**（不是只看开满那一刻）掩码都不超出目镜圆孔；
- 朝四个方向开镜都不出现矩形切割；
- 低倍 / 高倍瞄具都成立（验证倍率无关性）；
- 枪身贴脸（顶点擦过近平面）时掩码不炸成满屏。

## 2. 光影下镜内文字：不裁只是半边，另一边是黑块

### 2.1 症状

装光影包时，镜内文字（弹药计数那类 `text_show`）**画成黑块**；不装光影时完全正常。

### 2.2 真因：和「裁不裁」不是一个层

她 2026-08-30 那笔（`c4eb4e2`）修的是**裁切**：`IrisScopeMaskState` 补
`pipeline/scope_text_clipped → mode 2`。这条我们本仓也有（`c692059`），但它只解决
「镜外的像素丢不丢」。

黑块是**着色器谁接管**的问题：

- 文字走的是 `WORLD_TEXT_SNIPPET` 顶点格式 —— **没有法线、没有 lightmap**；
- `assignPipeline` 交给 Iris 之后，光影包用自己的 **HAND 程序**整条替换管线；
- HAND 程序按**实体格式**取法线与 lightmap，语义对不上 → 字形被采样成黑；
- 注入的 `tacz_ScopeMaskMode` 分支**只做 discard、不接管着色**——补 mode 能救裁切，救不了黑块。

### 2.3 我们的解法：别把文字交给 Iris

走**最终覆盖路线**：在 `LevelRenderer#render` 之后、用**冻结的手持变换**重画一遍，
管线是我们自己的，字形 / alpha 裁剪 / 目镜裁剪全部回到自己手里。

关键三件事：

1. **捕捉**：在手部 pass 期间把 `RenderSystem.getModelViewMatrixCopy()`（连同投影）
   存进一个 record——**必须在那一遍里抓**，晚一帧就抓不到了。
2. **排队**：文字与遮光环各自进队列（顺序号 20_001 / 20_002，都排在所有常规提交之后）。
3. **重放**：`flush()` 在帧末把捕捉到的矩阵压回 `RenderSystem.getModelViewStack()`，
   再用 `OrderedSubmitNodeCollector` 提交。
   管线用 `WORLD_TEXT_SNIPPET` + `withShaderDefine("SCOPE_MASK")` + `ScopeMaskSampler` 绑定组。

与 `ringFinal`（目镜遮光环）是**同一条先例**：那条管线的注释里也写了
「刻意不注册给 Iris，否则会被塞回光影管线，再被后置 pass 盖一次」。

### 2.4 两个「别做」

1. **别**把这条最终管线注册进 Iris 的 mode 表，也**别** assign 给 HAND——注册了就白做，
   又回到被 HAND 程序接管的状态。
2. **别**用「当前帧」的变换去重画：视角在那一遍之后还会变，文字会跟着漂。
   必须用**捕捉到的那份**。

### 2.5 验收

- 光影下镜内文字**可读**（不是黑块）、裁进目镜圆孔、开镜过程中不随视角漂；
- 无光影时行为与改动前一致（这条路只在装了光影且走了 Iris 接管时才有意义）；
- ttf / unihex 字体仍回退 vanilla 路径（已知边界，两边一致）。

**诚实状态**：本仓这一条是源码完成 + CI 编译过，**实机验收不在本轮范围内**，
本仓记录里查不到它的 PASS 依据。她那边照做之后需要自己实测。

## 3. 回单：mesh 第 1 步（GPU 静态烘焙）在她 PoC 基础上实机 PASS

本仓搬的是这四笔的**最终形态**（`f70867d→9f7412e` 聚合差；后三笔都是对第一笔的修正，
逐笔搬会把已修掉的 bug 搬回来）。

- 第一人称 `GPU-baked N bones …` 日志只出现一次（光照档 1 秒节流生效）；
